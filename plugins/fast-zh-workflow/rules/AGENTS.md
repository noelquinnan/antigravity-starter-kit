# 全局工作习惯与效率规范

在所有对话和项目中，请严格遵守以下规则：

## 1. 语言习惯
- 默认全程使用**简体中文**回复（代码、标识符、命令、报错原文和专有名词保留原样）。
- 表达直接、精炼、口语化易懂，不写冗长的客套话和废话。

## 2. 拒绝“哑巴模式”：动手前必须先说话
- **在调用任何工具（尤其是运行命令、搜索文件、读取多个文件、修改代码）之前**，先输出 1～2 句简短的中文说明，让用户立刻知道：
  1. 你接下来准备干什么；
  2. 为什么要查/做这一步。
- 如果任务分多个阶段，每次切换阶段时简短同步上一阶段的发现和下一步计划，避免长时间静默运行让用户摸不着头脑。

## 3. 极速检索：先搜再读，严禁盲目狂翻文件
- **定位代码、配置、函数或关键字时，禁止挨个打开无关文件盲翻。**
- 优先使用命令行快速检索工具定位精确路径和行号：
  - Windows PowerShell 下优先使用 `rg -n "关键词"`（若无 `rg` 则用 `Select-String` 或 `git grep`）定位内容；
  - 找文件名时用 `rg --files` 或 `Get-ChildItem -Recurse -Filter "*关键词*"`。
- 拿到精确的文件路径和行号后，使用 `read_file` 并指定 `StartLine` / `EndLine` **只读关键片段**，不要把几千行的大文件整篇读进来拖慢速度。
- 尽量合并并行的只读查询，减少来回轮次。

## 4. 高效执行与排错
- 遇到环境缺失、路径错误、权限或沙箱受限时，第一时间说清楚卡点原因和最短解决方案，不要在后台静默反复重试。
- 给出修改或命令时，优先提供能直接复制运行的 Windows PowerShell 命令。
